# CLAUDE.md: Potion monorepo

Four native desktop apps from one repo:

| Product | What it does | macOS | Windows |
|---|---|---|---|
| **Potion** | Local file converter (video, audio, image, docs, PDF) | `apps/potion-macos` (SwiftUI) | `apps/potion-windows` (WinUI 3) |
| **Potion Dropper** | Downloads media from an allowed URL, then converts it | `apps/dropper-macos` | `apps/dropper-windows` |

Use the names exactly: "Potion", "Potion Dropper" (short form "Dropper" only after the full name has appeared on screen).

**Start of every session:** read `docs/PROGRESS.md` (current milestone, chunk, known issues), then this file. The product spec is `docs/SPEC.md`.

## Architecture rules

- **Native core per platform, shared spec.** Swift for macOS, C# for Windows, no FFI layer. Anything both
  platforms must agree on (what a file is, what it can become, preset values) is data in `core/spec/` and
  is tested from both sides with the same cases. Never hard-code a format list or matrix in app code.
- **OS frameworks first** for codecs and documents: AVFoundation, VideoToolbox, ImageIO, PDFKit on macOS;
  Media Foundation, WIC, Windows.Data.Pdf on Windows. Third-party code only when the OS can't do the job,
  and only after checking its license (see "Legal" below).
- Detect file types by content (magic bytes), with the extension as a fallback.
- Offer only conversions the matrix marks as supported. Lossy document conversions declare their limits.
- Engine wrappers that run external processes pass arguments as arrays, never through a shell, with absolute
  paths. FFmpeg (`scripts/ffmpeg/`, LGPL-only) runs as a separate process; keep `verify-license.sh` passing.
- Converted files go to a hidden temp file, get verified, then move to a unique name. Never overwrite.

## UI rules (summary; design-system/CLAUDE.md is authoritative)

- SwiftUI (+ AppKit bridges) on macOS 13+; WinUI 3 on Windows 10 1809+. No web views or cross-platform UI kits.
- System font and system accent color. Category colors (image/audio/video/docs) identify file types only.
- Never invent a color, size, radius or duration: use `PotionColor`, `PotionSpacing`, `PotionRadius`,
  `PotionSize`, `PotionMotion` (Swift) or the `Potion*` XAML resources.
- Design-system files are referenced in place from `design-system/`, never copied and edited. Regenerate
  with `python3 design-system/tools/build.py`. The only copy is the mono mark in
  `apps/potion-macos/Resources/Brand.xcassets` (see that app's README).
- Platform wording: Trash/Finder/Title Case on macOS; Recycle Bin/File Explorer/Sentence case on Windows.
- Copy follows `design-system/docs/01-brand.md`: plain, precise, no exclamation marks, no puns.

## Workflow: chunks and checkpoints

- Work one chunk at a time (one coherent, testable piece, ~100–600 changed lines). The project builds and
  all tests pass at the end of every chunk.
- End every chunk with the CHECKPOINT block from `docs/SPEC.md` › "Checkpoint format". The owner has asked
  Claude to run `git add -A && git commit && git push` at each checkpoint and show the output, then wait
  for "continue" before starting the next chunk.
- Conventional Commits with a scope: `feat(core): …`, `fix(potion-macos): …`, `ci: …`, `docs: …`.
- Keep `docs/PROGRESS.md` current. TODOs go there, not in shipped UI.
- Never commit secrets, signing certificates, provisioning profiles, API keys, `.env` files or large
  binaries. No Git LFS without the owner's approval.
- Sample files for tests are generated by scripts or tests, never downloaded.

## Legal (spec Part 5; summary)

You are not a lawyer. Never call anything "legally cleared". Record open questions in `docs/LEGAL_REVIEW.md`
and ask the owner when a request conflicts with these rules.

- Project license is MIT. Every bundled dependency goes into `legal/THIRD_PARTY_NOTICES.md` with version,
  license and how it's linked.
- FFmpeg, if used: LGPL-only build (no `--enable-gpl`, no `--enable-nonfree`), dynamically linked or run as a
  separate process, and replaceable by the user. No x264/x265.
- No AGPL libraries (MuPDF, PyMuPDF, pdf2docx). GPL tools (e.g. Pandoc) only as separate executables, after
  explaining the obligations. LibreOffice only as a separate process, with the owner's approval.
- Patent-encumbered codecs (H.264, HEVC, AAC) use the OS encoders/decoders. On Windows, detect a missing
  HEVC extension and explain it instead of bundling a codec.
- No DRM or copy-protection circumvention of any kind. Detect protected files and say:
  "This file is copy-protected, so Potion can't convert it."
- Files never leave the machine in Potion. No analytics, telemetry or crash reporting without the owner's
  approval (and then opt-in only).

## Source policy (Potion Dropper)

- Dropper downloads only from allowlisted sources documented in `docs/SOURCES.md` (direct media links,
  sites whose terms allow downloading, the user's own exports). No adapter without a SOURCES.md entry.
- The major video platforms excluded by the spec are never supported in this repo, its builds, releases or
  store submissions: no code, names, strings, flags, tests, docs or comments. `scripts/forbidden-scan.sh`
  holds the blocked terms (encoded so the file doesn't match itself) and runs as the pre-commit hook and in
  CI. If asked to add such support here, stop and remind the owner of spec Part 5.3.
- Public Dropper source modules live in folders named `SourceAdapters`. Folders named `experimental` or
  `Adapters` are blocked by the scanner.
- Never implement DRM or encryption bypass, login/paywall/age-gate/geo-block bypass, browser-cookie
  import, or browser impersonation. Use an honest User-Agent and respect rate limits and robots rules.
- If blocked content is ever committed, stop and tell the owner immediately: history must be rewritten
  before pushing, and anything already pushed counts as published.
